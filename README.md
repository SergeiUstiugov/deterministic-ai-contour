# Двухконтурный маршрутизатор — рабочий прототип

Маленький, полностью локальный прототип к статье **«Новая индустриализация по-новому»**
и её приложениям. Показывает на коде то, о чём статья говорит словами: один контур
**предлагает**, второй — **проверяет**, и до оборудования доходит только проверенное.

Это **демонстрационный каркас, а не промышленный продукт.** Полевых метрик здесь нет.
Возьмите 5–10 задач своего цеха, подставьте их — и получите свою таблицу
«детерминированно / нужен ИИ».

## Что внутри (и как это связано со статьёй)

| Папка / файл | Что это | Термин в статье / приложении |
|---|---|---|
| `router/` | маршрутизатор: относит требование к контуру A / B1 / B2 / B3 | дерево выбора контура, Приложение A §8 |
| `checker/` | «программа-сторож»: разбирает код и проверяет по правилам | замкнутый контур, надёжный проверяющий |
| `checker/rules.py` | правила по нормам безопасности | аварийный сигнал, лимиты, anti-windup |
| `calibration/conformal.py` | честная оценка уверенности | класс B2, Приложение A §6 |
| `examples/` | примеры кода ST и набор задач | — |
| `benchmark.py` | таблица «детерминированно / нужен ИИ» | «что можно попробовать» из статьи |

Классы контуров (Приложение A §8):
- **A** — мягкое требование → открытый контур, предлагает ИИ;
- **B1** — жёсткое, есть дешёвая надёжная проверка → программа-сторож (поточечная гарантия);
- **B2** — жёсткое, проверки нет/дорого → честная оценка (без гарантии);
- **B3** — жёсткое, но правило может устареть → проверка + ревизия правила.

## Как запустить

Нужен только **Python 3.10+**, без внешних библиотек. Работает офлайн (air-gap).

```bash
# 1. Проверить «плохой» код контроллера — будет BLOCK (код возврата 1)
python -m checker.engine examples/bad_pump.st

# 2. Проверить исправленный код — будет OK (код возврата 0)
python -m checker.engine examples/good_pump.st

# 3. Прогнать набор задач и получить таблицу «детерминированно / нужен ИИ»
python benchmark.py

# 4. Посмотреть честную оценку (conformal) и как она ломается при сдвиге
python -m calibration.conformal
```

## Что демонстрируют примеры

`examples/bad_pump.st` — типичный черновик, который мог бы выдать ИИ. Сторож находит:
переменную без инициализации, интегратор без ограничения (нет anti-windup), только
один предел выхода, магические числа, прямую запись в защищённый тег. Итог — **BLOCK**.

`examples/good_pump.st` — тот же узел, но с инициализацией, зажимом интегратора,
обоими пределами и обработкой аварийного сигнала. Итог — **OK**.

## Принципы (из приложения A)

- **Запрет по умолчанию.** Если код не разобрался или проверка не пройдена — изменение
  блокируется, а не пропускается.
- **Честность гарантий.** B1 даёт поточечную гарантию только в пределах своих правил;
  это демонстрационный сканер строк, а не полный разбор IEC 61131-3. B2 даёт честную
  оценку, но не гарантию, и достоверна только при контроле сдвига распределения.
- ИИ здесь — в открытом контуре: он может писать черновик, но не имеет права
  сохранить изменение в обход сторожа.

## Как сделать «своим»

Откройте `examples/tasks.json`, замените задачи на свои (поля: `kind` = hard|soft;
`has_cheap_oracle`; `rule_may_be_stale`; `code` — путь к вашему `.st`). Запустите
`python benchmark.py` — получите долю задач, закрываемых детерминированно, именно для
вашего домена. Новые правила добавляются функциями в `checker/rules.py`.
