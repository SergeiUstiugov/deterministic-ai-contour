# Руководство: как разместить, запустить и отправить репозиторий

Пошаговая инструкция к прототипу **two-loop-router** (код к статье «Новая
индустриализация по-новому» и приложениям A, B). Рассчитана на Windows + PowerShell,
но команды запуска работают и в Linux/macOS. Внешних библиотек не нужно — только
**Python 3.10+**.

---

## Шаг 0. Что входит в комплект

```
two-loop-router/
├── README.md                     описание и примеры запуска
├── LICENSE                       MIT
├── requirements.txt              зависимостей нет (только Python 3.10+)
├── .gitignore
├── .github/workflows/ci.yml      автопроверка при каждом пуше (GitHub Actions)
├── router/router.py              маршрутизатор контуров A / B1 / B2 / B3
├── checker/                      «программа-сторож» (замкнутый контур)
│   ├── st_parser.py              мини-разбор Structured Text
│   ├── rules.py                  6 правил безопасности
│   └── engine.py                 вердикт OK / WARN / BLOCK
├── calibration/conformal.py      честная оценка уверенности (класс B2)
├── examples/
│   ├── bad_pump.st               плохой черновик  -> BLOCK
│   ├── good_pump.st              исправленный      -> OK
│   └── tasks.json                10 задач для бенчмарка
├── benchmark.py                  таблица «детерминированно / нужен ИИ»
├── tests/test_checker.py         самопроверка (9 тестов)
└── docs/                         приложения к статье
    ├── Приложение_A_Теория_двухконтурной_архитектуры.docx
    └── Приложение_B_Industrial_AI_OS_Siemens_NVIDIA.docx
```

## Шаг 1. Куда положить файлы

Если вы обновляете существующий репозиторий — распакуйте архив и скопируйте всё его
содержимое в корень папки репозитория, сохранив структуру выше. Папки `tests`,
`.github` и `docs` должны оказаться рядом с `benchmark.py`.

---

## Шаг 2. Проверить, что код запускается (локально)

Выполняйте команды **из корня репозитория** (там, где лежит `benchmark.py`).

```powershell
# 1) Самопроверка — должно быть "OK" и 9 пройденных тестов
python -m unittest discover -s tests -v

# 2) Проверка плохого кода — вердикт BLOCK (код возврата 1)
python -m checker.engine examples/bad_pump.st

# 3) Проверка исправленного кода — вердикт OK (код возврата 0)
python -m checker.engine examples/good_pump.st

# 4) Таблица «детерминированно / нужен ИИ»
python benchmark.py

# 5) Честная оценка и её срыв при сдвиге распределения
python -m calibration.conformal
```

**Если на Windows в выводе «кракозябры»** — это кодировка консоли, не ошибка.
Лечится разово одной из команд:

```powershell
chcp 65001
# или
python -X utf8 benchmark.py
```

## Шаг 3. Разместить приложения (docx)

Приложения A и B уже лежат в папке `docs/`. На GitHub файлы `.docx` не открываются
прямо в браузере — будет только кнопка «скачать». Если нужен просмотр онлайн, можно
дополнительно положить в `docs/` их PDF-версии и ссылаться на них.

## Шаг 4. Отправить в репозиторий (Git)

```powershell
cd "путь\к\репозиторию"

git add .
git commit -m "Прототип двухконтурного маршрутизатора: код, тесты, CI, приложения"
git push origin main
```

---

## Шаг 5. Проверить автопроверку (CI)

После пуша откройте репозиторий на GitHub → вкладка **Actions**. Там запустится
рабочий процесс **CI**: он прогонит тесты и бенчмарк на Python 3.10, 3.11 и 3.12.
Зелёная галочка означает, что код запускается у любого, кто его склонирует.
Файл процесса — `.github/workflows/ci.yml`, менять его не нужно.

---

## Шаг 6. Как сделать «своим»

1. **Свои задачи.** Откройте `examples/tasks.json`, замените задачи на задачи своего
   цеха. Поля: `kind` = `hard` либо `soft`; `has_cheap_oracle` — есть ли дешёвая
   надёжная проверка; `rule_may_be_stale` — может ли правило устареть; `code` — путь
   к вашему файлу `.st` (необязательно). Запустите `python benchmark.py` — получите
   свою долю «детерминированно / нужен ИИ».
2. **Свои правила.** Добавьте функцию-правило в `checker/rules.py` и впишите её в
   список `ALL_RULES`. Каждое правило возвращает список находок (`Finding`) с
   тяжестью `BLOCK` или `WARN`.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `ModuleNotFoundError: checker` | запускаете не из корня репозитория — перейдите в папку с `benchmark.py` |
| «кракозябры» в выводе на Windows | кодировка консоли: `chcp 65001` или `python -X utf8 ...` |
| `python` не найден | установите Python 3.10+ и отметьте «Add to PATH» |
| тест падает | проверьте, что папки `examples/`, `checker/`, `router/`, `calibration/` на месте и не переименованы |
